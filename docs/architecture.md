# Архитектура и протокол версии 0.6

## Компоненты

`SecondScreen` запускает отдельный `VirtualDisplayHelper`, создающий CGVirtualDisplay с выбранным разрешением/частотой и уникальным стабильным serial для каждого профиля. Помощник живёт, пока открыта входная труба родителя; завершение процесса освобождает виртуальный дисплей. После создания выбирается режим нужного разрешения, чтобы не использовать ранее закэшированное разрешение macOS.

`MonitorLibrary` хранит Codable-профили в UserDefaults, переносит одиночный профиль 0.5 и ограничивает число одновременно подключаемых экранов тремя. Каждый `MonitorSession` владеет собственными TVConnection, SecondScreen, ScreenPreview и VideoEncoder. Потеря связи завершает только соответствующий экран. Геометрия вычисляется относительно встроенного дисплея Mac в координатах CoreGraphics; несколько экранов на одной стороне последовательно примыкают друг к другу. Изменение расположения подключённых экранов применяется одной транзакцией CGDisplayConfiguration.

`DisplayCapabilities` на Android получает физические режимы через Display.getSupportedModes, пересекает их с areSizeAndRateSupported аппаратных AVC-декодеров и добавляет уменьшенные варианты 1080p/720p с выводом в поддерживаемом физическом режиме TV. Передача ограничена 3840 × 2160 / 120 Гц. Автовыбор максимизирует сначала число пикселей, затем частоту. Внешний режим TV выбирается через preferredDisplayModeId, Surface получает подсказку частоты через setFrameRate. macOS может представлять дробную частоту виртуального экрана номинальным значением; реальная частота показа измеряется отдельно на Android.

Отдельный read-only TCP-сервис 8846 сообщает только JSON режимов и версию протокола. Он работает, пока открыт приёмник, и не передаёт код, токены или изображение. PresenceProbe ограничивает чтение 16 КиБ и тайм-аутом 2 секунды; список проверяется примерно каждые 5 секунд. Это публичное объявление не даёт доверия устройству: окончательный список режимов повторно приходит внутри закреплённого TLS после авторизации, а Android проверяет выбранный режим перед декодированием.

`ScreenPreview` использует ScreenCaptureKit для захвата только виртуального экрана. CVPixelBuffer поступает напрямую кодировщику. Локальный предпросмотр обновляется реже (около 5 раз/с), чем видеопоток. Захват имеет потолок вдвое выше целевой частоты, чтобы не добавлять ограничение со стороны capture callback.

`VideoEncoder` требует аппаратный VideoToolbox H.264, включает low-latency/real-time, запрещает B-кадры, задаёт выбранную частоту, масштабирует битрейт от 18 Мбит/с для Full HD / 60 (2–80 Мбит/с), задаёт интервал ключевого кадра около 2 секунд. AVCC преобразуется в Annex B; SPS/PPS передаются отдельно. Семафор ограничивает число кадров в обработке шестью. Если очередь заполнена, пропускается исходный кадр до кодирования; зависимые закодированные кадры произвольно не выбрасываются.

`TVConnection` обнаруживает приёмник и сверяет сертификат, авторизуется кодом, передаёт конфигурацию и видеопакеты. Подтверждения принятия освобождают очередь, а счётчики показа и FPS поступают независимо. При потере сеанса UI останавливает захват и удаляет второй экран.

`VideoDecoder` выбирает аппаратный H.264 MediaCodec, поддерживающий выбранные разрешение и частоту. Сетевой поток подаёт входные пакеты, отдельный поток извлекает выход и сразу направляет его в SurfaceView. MediaCodec.OnFrameRenderedListener сообщает число показанных кадров и частоту по временным меткам в окне 2 секунды.

## Защита и срок жизни

Приёмник слушает TCP 8845 только пока открыт его экран; используется TLS 1.2. Код и изображение не отправляются до проверки полного SHA-256 сертификата. UI показывает сокращённый номер (48 бит, три группы по четыре шестнадцатеричных символа) для сверки владельцем на обоих устройствах. Первое обнаружение получает сертификат без передачи кода.

На прошивках, где AndroidKeyStore не создаёт ключ, используется постоянная RSA-идентичность Bouncy Castle. Она хранится в закрытом внутреннем no-backup хранилище приложения (AtomicFile / PKCS12); в APK общего закрытого ключа нет. Номер TV сохраняется между перезапусками. Очистка данных приложения удаляет эту идентичность; резервное копирование отключено.

При первом сопряжении код с экрана TV разрешает выдачу случайного 256-битного токена этому Mac. TV сохраняет SHA-256 токена с UUID клиента в закрытых SharedPreferences; Mac сохраняет токен и полный SHA-256 сертификата в login Keychain. Название, IP и публичный UUID клиента хранятся отдельно в настройках. При повторном подключении Mac проверяет исходный сертификат, затем передаёт токен внутри TLS. Изменение сертификата не принимается автоматически. Код после отключения меняется; доверенный токен продолжает работать. Приёмник ограничивает неверные попытки тремя в минуту и сохраняет до 16 Mac.

«Забыть подключение» на Mac удаляет локальную запись Keychain. «Забыть все Mac» на TV удаляет разрешённые токены и закрывает сеанс. Повторное сопряжение того же UUID заменяет его старый токен. При изменении IP запись доверия не переносится автоматически на новый адрес.

Кадры и звук во время обычной работы не сохраняются в файлы. Диагностика может показывать названия локальных окон/процессов. Тестовый режим сохранения снимка включается отдельно; его результаты исключены из Git.

## Wire format (BLUSCR04)

Все целые числа — big endian.

1. Внутри TLS: ASCII `BLUSCR04`, u8 режим (0 — первое сопряжение, 1 — сохранённое доверие), UUID клиента (36 ASCII-байтов), затем шесть ASCII-цифр кода для режима 0 или 32 байта токена для режима 1.
2. Приёмник отвечает байтом: 1 — успешно, 0 — отказ. При успехе следуют 32 байта токена: новый для режима 0, исходный для режима 1. Mac сохраняет токен только после TLS с закреплённым сертификатом.
3. Приёмник передаёт u32 длины и JSON режимов (до 16 КиБ, protocolVersion=4). Затем отправитель выбирает из них режим и передаёт три u32: ширина, высота, частота × 1000 (например 59940).
4. Пакеты: длина payload u32, затем payload. Нулевая длина — heartbeat.
5. Ненулевой payload: тип u8 (1 — SPS/PPS, 2 — Annex B sample), временная метка u64 в микросекундах, данные. Максимум пакета — 2 МиБ.
6. Обратная связь: три u32 — число принятых кадров, число показанных кадров, измеренный FPS × 1000.

Heartbeat раз в 3 секунды; отсутствие обратной связи 8 секунд завершает сеанс. Номинальные 60 в настройках потока не являются доказательством частоты показа. Версии 0.3–0.5 несовместимы с 0.6 по формату протокола: обновлять нужно обе стороны. Сохранённые TLS-идентичность и токены сопряжения при штатном обновлении сохраняются.

## Воспроизведение измерения

Сначала собрать проект, открыть приёмник на своём устройстве и выдать необходимые разрешения macOS. Тест создаёт отдельный экран с движущейся голубой полосой и передаёт реальный захват.

```sh
xcrun swiftc -parse-as-library -swift-version 5 -O -target arm64-apple-macosx14.2 -import-objc-header Sources/VirtualDisplay.h Sources/DisplayMode.swift Sources/Diagnostics.swift Sources/SecondScreen.swift Sources/ScreenPreview.swift Sources/VideoEncoder.swift Sources/TVConnection.swift Tests/VideoEndToEnd.swift build/VirtualDisplay.o -o build/video-end-to-end
read -s BLUESCREEN_TEST_PIN
export BLUESCREEN_TEST_PIN
build/video-end-to-end TV_IP DEVICE_NUMBER 90
unset BLUESCREEN_TEST_PIN
```

`DEVICE_NUMBER` — номер с TV вида `ABCD-1234-EF56`; `TV_IP` заменяется фактическим локальным IPv4. Код вводится локально, не включайте его в отчёты/коммиты. Результат — `evidence/full-hd-benchmark.json`, частота берётся из `rendered_fps_window`. Тест завершает сеанс и восстанавливает исходные экраны. Флаг `BLUESCREEN_CAPTURE_EVIDENCE=1` сохраняет снимок источника на пятой секунде; для измерения производительности его не включать. PASS означает прохождение тракта, соответствие целевой частоте оценивается отдельно по выборкам после разгона.

## Проверка нескольких экранов

`zsh Tools/check-monitors.sh` проверяет сериализацию профилей, ранжирование/границы режимов, геометрию четырёх направлений и цепочки экранов, запрет четвёртого подключения. Затем реально создаёт три независимых виртуальных дисплея разного размера, перемещает экран и восстанавливает исходный набор. На текущем стенде физически доступен один TV; три параллельных физических приёмника и их суммарная производительность не подтверждены.

Мониторинг доступности не обращается к Keychain и не прерывает активное видео. События отключения/остановки захвата фильтруются removeDuplicates: повторное присваивание false при подготовке соединения не должно запускать параллельную очистку нового экрана.
